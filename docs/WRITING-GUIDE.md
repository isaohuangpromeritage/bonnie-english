# 文章寫作規格

新增文章請遵守這份規格，寫完執行 `node tools/check-articles.mjs <檔案>` 修到全部通過。

## 1. 級別

| | A 基礎（七、八年級） | B 進階（八、九年級） |
|---|---|---|
| 字數 | 100～200 字（圖表題、對話不限下限） | 160～300 字 |
| 用字 | 以教育部 1200 基本字為主；常用 2000 字最多 6 個 | 2000 字範圍內 |
| 超綱字 | 最多 1 個 | 最多 3 個（文章下方自動加註） |
| 句型 | 簡單句、現在式、過去式、未來式、祈使句、and/but/so/because | 再加上：關係子句、被動語態、比較級與最高級、現在完成式、不定詞與動名詞、if/when/although |
| 題數 | 3～4 題 | 4～5 題 |

特定主題非用不可的超綱字（例如動漫文章的 anime、manga），列在文章的 `keywords`（最多 3 個），不計入超綱上限，文章下方一樣會自動加註。這些字要先在 `data-src/curated.json` 收錄並重建字典。

用字檢查以 `data/dict.json` 為準（字級來自教育部 2000 字表）。人名、地名、品牌名列在文章的 `names` 欄位，不算生字。

## 2. 文體（genre）

| genre | 說明 | 常用區塊 |
|---|---|---|
| 記敘文 | 生活故事、寓言、人物經歷 | `p` |
| 說明文 | 科學、動物、文化、節慶、健康、環保 | `p`（可加 `h` 小標題） |
| 圖表題 | 廣告、公告、菜單、時刻表、行事曆、海報、規則 | `notice` |
| 書信 | email、卡片、網路留言、日記 | `email`、`p` |
| 對話 | 聊天訊息、對話 | `chat` |
| 多文本 | 兩篇以上的文本，例如兩則意見、一篇文章加一張表 | `h` 標出 Text A／Text B，再接其他區塊 |

## 3. 主題（topic）

用教育部字表的主題名稱，每篇一個：
學校、食物與飲料、房屋與居家、動物與昆蟲、運動與嗜好、時間、職業、衣物與配件、地點與場所、交通、天氣與自然、人物、身體部位、健康、家庭、金錢、地理、節日、國家與地區、顏色、尺寸與度量。

內容盡量放在台灣學生熟悉的情境（捷運、夜市、颱風假、校慶、補習、便利商店……），但不要寫出真實的店名、品牌或真人。

## 4. JSON 格式

```json
{
  "id": "night-market",            // 英文小寫加連字號，不可重複
  "level": "A",
  "genre": "圖表題",
  "title": "Lin's Night Market Snacks",
  "zh": "林家夜市小吃",
  "topic": "食物與飲料",
  "grade": 7,                      // 建議年級 7／8／9
  "grammar": "數字與價格、祈使句",  // 文章的文法重點（中文）
  "names": ["Lin"],                // 文中的人名、地名（大小寫要和文中一樣）
  "keywords": ["anime"],           // 主題關鍵超綱字（可省略，最多 3 個）
  "tags": ["動漫"],                // 專題標籤（可省略），列表可依標籤篩選
  "blocks": [ ... ],
  "questions": [ ... ]
}
```

### 區塊（blocks）

```json
{ "t": "p", "x": "一段文字" }
{ "t": "h", "x": "Text A: Amy's Opinion" }
{ "t": "notice", "title": "標題", "sub": "副標（可省略）",
  "rows": [["表頭1", "表頭2"], ["資料", "資料"]],   // 表格（可省略）
  "items": ["條列一", "條列二"],                   // 條列（可省略）
  "foot": "結尾一句（可省略）" }
{ "t": "chat", "lines": [ { "who": "Amy", "x": "Hi!" }, { "who": "Me", "x": "Hello!", "me": true } ] }
{ "t": "email", "from": "Kenji", "to": "Mei", "subject": "My trip", "body": ["第一段", "第二段"] }
```

- 時間用 24 小時制（14:30），不要用 a.m./p.m.
- 價格用 $（例如 $120），不要用 NT$
- 不要用縮寫的星期以外的縮寫（Mon、Tue 可以）

### 題目（questions）

```json
{
  "type": "細節",
  "question": "What time does the bus leave?",
  "options": ["…", "…", "…", "…"],
  "answer": "B",
  "explanation": "中文解析，引用原文：「The bus leaves at 8:30.」所以選 B。"
}
```

- type：主旨、細節、推論、字義猜測、指涉、圖表判讀、計算、整合（多文本）、作者目的
- 每篇至少 3 種題型；圖表題要有圖表判讀或計算；多文本要有整合題
- 題目和選項用英文，用字一樣不能超過級別範圍
- 答案一定要能從文中找到依據，不能靠課外常識答對
- 錯誤選項要「看起來可能」：文中出現過但不是題目問的、部分正確、把人物或數字對調
- 正確答案的位置平均分散在 A～D，不要都是同一個字母，也不要永遠是最長的選項
- 解析用繁體中文，指出依據的原文句子，必要時說明其他選項錯在哪裡

## 5. 以真實作品為題材時（例如動漫、電影）

- 寫「關於」作品的文章：介紹、心得、主題討論、粉絲活動，不要改寫或重述劇情片段
- 不要引用作品的台詞、口號或歌詞，人物對話要自己寫
- 只寫廣為人知、不會變動的基本設定（作者、主角、故事前提），不要寫集數、銷量、播出日期這類容易過時或記錯的數字
- 不放作品圖片、標誌

## 6. 單題練習（data/singles.json）

仿會考第一部分「單題」：一句話（或兩句小對話）挖一個空格，四選一。題目全部原創，不可抄錄會考或其他考卷的題目。

```json
{
  "id": "g-tense-001",              // 文法 g-、字彙 v-，不可重複
  "level": "A",                     // A：七、八年級程度；B：八、九年級程度
  "cat": "文法",                    // 文法 或 字彙
  "point": "過去簡單式",            // 考點，見下表
  "question": "Tom ____ his homework before dinner yesterday.",
  "options": ["finishes", "finished", "will finish", "is finishing"],
  "answer": "B",
  "explanation": "yesterday 表示過去，動詞用過去式 finished。",
  "names": ["Tom"]                  // 人名（可省略）
}
```

- 空格寫成 `____`（4 個以上底線）；對話題用 `\n` 分行，例如 `"A: …\nB: ____"`
- 考點（point）：
  - 文法：現在簡單式、過去簡單式、進行式、未來式、現在完成式、助動詞、被動語態、比較級與最高級、代名詞、關係子句、附加問句、不定詞與動名詞、連接詞、間接問句、介系詞、名詞與冠詞、感官與使役動詞、句型
  - 字彙：名詞、動詞、形容詞、副詞、片語與搭配、情境對話
- 用字：A 級題目與選項都要在 2000 字內（不可有超綱字），B 級最多 1 個
- 字彙題的四個選項詞性要相同，錯誤選項要「放進句子文法通、但意思不對」
- 文法題要有明確的判斷線索（時間副詞、主詞單複數、先行詞等），解析要點出線索
- 只能有一個正確答案；解析用繁體中文，說明為什麼對、常見錯誤選項為什麼錯
- 寫完執行 `node tools/check-singles.mjs <檔案>` 修到全部通過，再做盲測
